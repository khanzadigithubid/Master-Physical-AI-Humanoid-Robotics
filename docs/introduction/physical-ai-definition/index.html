Formal Definition of Physical AI

Introduction​

This chapter provides a rigorous mathematical framework for Physical AI systems. We formalize embodied agents as dynamical systems that sense, compute, and act in continuous physical environments.

Mathematical Framework​

The Embodied Agent​

A Physical AI agent is defined as a tuple:

A=(S,A,O,fdynamics,fpolicy,fperception)\mathcal{A} = (\mathcal{S}, \mathcal{A}, \mathcal{O}, f_{\text{dynamics}}, f_{\text{policy}}, f_{\text{perception}})A=(S,A,O,fdynamics​,fpolicy​,fperception​)

Where:

  • S\mathcal{S}S: State space (robot configuration + environment state)
  • A\mathcal{A}A: Action space (motor commands)
  • O\mathcal{O}O: Observation space (sensor measurements)
  • fdynamics:S×A→Sf_{\text{dynamics}}: \mathcal{S} \times \mathcal{A} \rightarrow \mathcal{S}fdynamics​:S×A→S: Physical dynamics
  • fpolicy:O→Af_{\text{policy}}: \mathcal{O} \rightarrow \mathcal{A}fpolicy​:O→A: Control policy
  • fperception:S→Of_{\text{perception}}: \mathcal{S} \rightarrow \mathcal{O}fperception​:S→O: Sensor model

State Space S\mathcal{S}S​

The state consists of:

  1. Robot configuration q∈Rnq \in \mathbb{R}^nq∈Rn: Joint angles, positions
  2. Robot velocity q˙∈Rn\dot{q} \in \mathbb{R}^nq˙​∈Rn: Joint velocities
  3. Environment state senvs_{\text{env}}senv​: Object poses, terrain geometry

For a humanoid robot with nnn joints:

S={(q,q˙,senv)∣q∈Rn,q˙∈Rn,senv∈E}\mathcal{S} = \{(q, \dot{q}, s_{\text{env}}) \mid q \in \mathbb{R}^n, \dot{q} \in \mathbb{R}^n, s_{\text{env}} \in \mathcal{E}\}S={(q,q˙​,senv​)∣q∈Rn,q˙​∈Rn,senv​∈E}

Example: Atlas humanoid has n=28n=28n=28 actuated joints, so q∈R28q \in \mathbb{R}^{28}q∈R28.

Action Space A\mathcal{A}A​

Actions are motor commands:

  • Position control: a=qdesired∈Rna = q_{\text{desired}} \in \mathbb{R}^na=qdesired​∈Rn
  • Velocity control: a=q˙desired∈Rna = \dot{q}_{\text{desired}} \in \mathbb{R}^na=q˙​desired​∈Rn
  • Torque control: a=τ∈Rna = \tau \in \mathbb{R}^na=τ∈Rn

Action bounds: a∈[amin⁡,amax⁡]a \in [\mathbf{a}_{\min}, \mathbf{a}_{\max}]a∈[amin​,amax​]

Example: For torque control, typical bounds are τi∈[−150,150]\tau_i \in [-150, 150]τi​∈[−150,150] Nm per joint.

Observation Space O\mathcal{O}O​

Observations are partial and noisy sensor measurements:

ot=fperception(st)+ϵt,ϵt∼N(0,Σsensor)o_t = f_{\text{perception}}(s_t) + \epsilon_t, \quad \epsilon_t \sim \mathcal{N}(0, \Sigma_{\text{sensor}})ot​=fperception​(st​)+ϵt​,ϵt​∼N(0,Σsensor​)

Sensor types:

  1. Proprioception: Joint encoders (qt,q˙tq_t, \dot{q}_tqt​,q˙​t​), IMU (orientation, angular velocity)
  2. Exteroception: Cameras (RGB images), LiDAR (point clouds), force/torque sensors

Example: Camera observation ocam∈RH×W×3o_{\text{cam}} \in \mathbb{R}^{H \times W \times 3}ocam​∈RH×W×3 (e.g., 640×480×3640 \times 480 \times 3640×480×3).

Physical Dynamics​

Continuous-Time Dynamics​

The robot's physical evolution is governed by:

ddt[qq˙]=[q˙M(q)−1(τ−C(q,q˙)−G(q))]\frac{d}{dt} \begin{bmatrix} q \\ \dot{q} \end{bmatrix} = \begin{bmatrix} \dot{q} \\ M(q)^{-1} (\tau - C(q, \dot{q}) - G(q)) \end{bmatrix}dtd​[qq˙​​]=[q˙​M(q)−1(τ−C(q,q˙​)−G(q))​]

Where:

  • M(q)∈Rn×nM(q) \in \mathbb{R}^{n \times n}M(q)∈Rn×n: Inertia matrix
  • C(q,q˙)∈RnC(q, \dot{q}) \in \mathbb{R}^nC(q,q˙​)∈Rn: Coriolis and centrifugal forces
  • G(q)∈RnG(q) \in \mathbb{R}^nG(q)∈Rn: Gravitational forces
  • τ∈Rn\tau \in \mathbb{R}^nτ∈Rn: Applied joint torques (our action aaa)

This is the Euler-Lagrange equation from analytical mechanics.

Discrete-Time Dynamics​

For control at timestep Δt\Delta tΔt:

st+1=fdynamics(st,at)+wt,wt∼N(0,Σprocess)s_{t+1} = f_{\text{dynamics}}(s_t, a_t) + w_t, \quad w_t \sim \mathcal{N}(0, \Sigma_{\text{process}})st+1​=fdynamics​(st​,at​)+wt​,wt​∼N(0,Σprocess​)

Discretization methods:

  • Euler integration: qt+1=qt+q˙tΔtq_{t+1} = q_t + \dot{q}_t \Delta tqt+1​=qt​+q˙​t​Δt
  • Runge-Kutta (RK4): Higher-order accuracy
  • Physics simulators: MuJoCo, Isaac Sim use implicit integrators

Example: At Δt=0.01\Delta t = 0.01Δt=0.01 s (100 Hz control), a humanoid takes discrete steps.

Control Policies​

Policy Types​

1. Reactive Policy (feedforward):

at=π(ot)a_t = \pi(o_t)at​=π(ot​)

2. Recurrent Policy (memory-based):

at=π(ot,ht),ht+1=fRNN(ht,ot)a_t = \pi(o_t, h_t), \quad h_{t+1} = f_{\text{RNN}}(h_t, o_t)at​=π(ot​,ht​),ht+1​=fRNN​(ht​,ot​)

3. Model-Based Policy (planning):

at=arg⁡max⁡aEst+1∼fmodel[R(st+1)]a_t = \arg\max_{a} \mathbb{E}_{s_{t+1} \sim f_{\text{model}}} [R(s_{t+1})]at​=argamax​Est+1​∼fmodel​​[R(st+1​)]

Parameterization​

Modern policies are neural networks:

πθ:O→A,θ∈Rd\pi_\theta: \mathcal{O} \rightarrow \mathcal{A}, \quad \theta \in \mathbb{R}^dπθ​:O→A,θ∈Rd

Example architectures:

  • MLP: 3 hidden layers, 256 units each, ∼\sim∼200k parameters
  • CNN: For image observations (ResNet-18 backbone)
  • Transformer: For sequence modeling (e.g., language-conditioned manipulation)

Learning Objective​

Find optimal policy π∗\pi^*π∗ that maximizes cumulative reward:

π∗=arg⁡max⁡πEτ∼π[∑t=0∞γtr(st,at)]\pi^* = \arg\max_\pi \mathbb{E}_{\tau \sim \pi} \left[ \sum_{t=0}^\infty \gamma^t r(s_t, a_t) \right]π∗=argπmax​Eτ∼π​[t=0∑∞​γtr(st​,at​)]

Where τ=(s0,a0,s1,a1,…)\tau = (s_0, a_0, s_1, a_1, \ldots)τ=(s0​,a0​,s1​,a1​,…) is a trajectory and γ∈[0,1)\gamma \in [0, 1)γ∈[0,1) is the discount factor.

Perception Models​

Forward Sensor Model​

Given true state sts_tst​, predict observation:

p(ot∣st)=N(fperception(st),Σsensor)p(o_t \mid s_t) = \mathcal{N}(f_{\text{perception}}(s_t), \Sigma_{\text{sensor}})p(ot​∣st​)=N(fperception​(st​),Σsensor​)

Example: Camera renders image of scene given object poses.

Inverse Sensor Model (State Estimation)​

Given observation history o1:to_{1:t}o1:t​, estimate state:

p(st∣o1:t)∝p(ot∣st)∫p(st∣st−1,at−1)p(st−1∣o1:t−1)dst−1p(s_t \mid o_{1:t}) \propto p(o_t \mid s_t) \int p(s_t \mid s_{t-1}, a_{t-1}) p(s_{t-1} \mid o_{1:t-1}) ds_{t-1}p(st​∣o1:t​)∝p(ot​∣st​)∫p(st​∣st−1​,at−1​)p(st−1​∣o1:t−1​)dst−1​

This is the Bayes filter. Implementations:

  • Kalman Filter: Linear-Gaussian case
  • Extended Kalman Filter (EKF): Nonlinear via linearization
  • Particle Filter: Nonparametric, handles multi-modal distributions

Comparison: Software AI vs. Physical AI​

PropertySoftware AIPhysical AI
State spaceDiscrete (tokens, pixels)Continuous (Rn\mathbb{R}^nRn)
DynamicsDeterministic (GPU compute)Stochastic (physics + noise)
ObservationPerfect (access to state)Partial (sensor measurements)
Action spaceDiscrete (text generation)Continuous (motor commands)
Feedback delayNone (instant compute)10-100ms (actuation lag)
SafetyMistakes are cheap (regenerate)Mistakes are costly (hardware damage)
EvaluationOffline metrics (accuracy)Online performance (task success)

Key Insight: Physical AI must handle continuous state spaces, partial observability, action delays, and safety constraints.

The Embodiment Hypothesis​

Thesis: Intelligence is fundamentally grounded in sensorimotor experience.

Evidence:

  1. Human development: Motor skills precede abstract reasoning (Piaget's stages)
  2. Animal cognition: Navigation requires spatial memory (hippocampus place cells)
  3. AI progress: Foundation models (GPT-4) lack common-sense physics understanding

Implications for Physical AI:

  • Learning from interaction: RL >> supervised learning for control
  • Multimodal perception: Vision + touch + proprioception
  • Active sensing: Move to gain information (e.g., look around occluder)

Goal: Grasp a cup on a table

State sts_tst​​

  • Robot: (q,q˙)(q, \dot{q})(q,q˙​) (7-DOF arm + 2-finger gripper)
  • Environment: Cup pose (x,y,z,orientation)(x, y, z, \text{orientation})(x,y,z,orientation)

Action ata_tat​​

  • End-effector velocity command: (vx,vy,vz)∈R3(v_x, v_y, v_z) \in \mathbb{R}^3(vx​,vy​,vz​)∈R3
  • Gripper command: close\text{close}close or open\text{open}open

Observation oto_tot​​

  • RGB-D camera: 640×480640 \times 480640×480 depth image
  • Proprioception: Joint angles qqq, gripper width

Dynamics fdynamicsf_{\text{dynamics}}fdynamics​​

  • Forward kinematics: Map q→q \rightarrowq→ end-effector pose
  • Contact physics: Gripper closes → force on cup

Policy π(o)\pi(o)π(o)​

  • CNN: Encode RGB-D image to feature vector
  • MLP: Map features + proprioception → velocity command

  • +10+10+10 if cup grasped

Challenges Unique to Physical AI​

1. Compounding Errors​

Small perception errors → incorrect actions → worse state → harder perception.

Example: Localization error of 5cm → manipulator misses object → task failure.

Mitigation: Closed-loop control, robust perception, error recovery behaviors.

2. Irreversibility​

Unlike software, some actions cannot be undone.

Example: Dropping a glass → permanent damage.

Mitigation: Safe exploration (constrained RL), human supervision, redundant grippers.

3. Sample Complexity​

Real-world data is expensive (hardware wear, human supervision, energy).

Example: Learning to walk might require 100,000 falls → infeasible on hardware.

Mitigation: Simulation (Isaac Sim, MuJoCo), sim-to-real transfer, imitation learning.

4. Latency​

Sensor → compute → actuator pipeline introduces delay.

Example: 50ms latency → robot reacts to outdated observation.

Mitigation: Predictive models, fast control loops (1kHz), model-based RL.

Summary​

Physical AI systems are formalized as embodied agents (S,A,O,fdynamics,fpolicy,fperception)(\mathcal{S}, \mathcal{A}, \mathcal{O}, f_{\text{dynamics}}, f_{\text{policy}}, f_{\text{perception}})(S,A,O,fdynamics​,fpolicy​,fperception​) that:

  1. Sense the world through noisy, partial observations oto_tot​
  2. Compute actions at=π(ot)a_t = \pi(o_t)at​=π(ot​) via learned policies
  3. Act in the world, subject to continuous physical dynamics st+1=f(st,at)s_{t+1} = f(s_t, a_t)st+1​=f(st​,at​)
  4. Learn from interaction to maximize cumulative reward

This framework unifies robotics and AI, enabling mathematical analysis of:

  • Optimal control (finding π∗\pi^*π∗)
  • State estimation (inferring sts_tst​ from o1:to_{1:t}o1:t​)
  • Sim-to-real transfer (bridging simulation fsimf_{\text{sim}}fsim​ and reality frealf_{\text{real}}freal​)

Key Takeaways​

✅ Physical AI agents are defined by state space S\mathcal{S}S, action space A\mathcal{A}A, and observation space O\mathcal{O}O

✅ Physical dynamics fdynamicsf_{\text{dynamics}}fdynamics​ govern continuous evolution via Euler-Lagrange equations

✅ Policies π:O→A\pi: \mathcal{O} \rightarrow \mathcal{A}π:O→A are typically neural networks trained with RL

✅ Perception models fperceptionf_{\text{perception}}fperception​ map true state to noisy sensor measurements

✅ Physical AI differs from software AI in continuous state/action spaces, partial observability, and safety constraints
